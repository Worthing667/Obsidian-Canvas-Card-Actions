# 技术实现：卡片合并

本文档说明 `Canvas Loom` 当前版本中“卡片合并 / Loom工作台 / 卡片组预览”功能的实现方式。这里记录的是已经落地的代码结构，而不是早期方案草稿。

## 1. 当前交互结构

多选卡片后的主交互已经收敛为三条入口：

- `一键复制`
- `一键拼合`
- `预览卡片组`

对应关系如下：

- `一键复制`：按设置 `defaultSortMode` 直接生成文本并写入剪贴板
- `一键拼合`：按设置 `defaultSortMode` 直接在当前 Canvas 新建卡片，并按 `mergeCleanupMode` 决定是否删除源卡片
- `预览卡片组`：把当前选区载入常驻 Loom工作台，在其中切换排序、预览结果，并执行输出

旧的合并命令仍然保留在命令面板中：

- `MergeToCanvasCardCommand`
- `MergeToSidebarPreviewCommand`
- `MergeToMarkdownCommand`
- `ManualMergeCommand`

但它们已经不再挂载到多选右键菜单。

## 3. 命令层设计

### 3.1 快速命令

`src/presentation/commands/QuickActionCommands.ts`

新增了三类快速命令：

- `QuickCopyCommand`
- `QuickMergeCommand`
- `OpenPreviewWorkbenchCommand`

它们的特点是：

- 都接收当前选区快照来源
- 都读取统一设置 `defaultSortMode`
- `QuickMergeCommand` 还读取 `mergeCleanupMode`
- 都不再让右键菜单同时暴露“排序方式”和“输出方式”两个维度

### 3.2 旧命令兼容

`src/presentation/commands/MergeCommands.ts`

旧命令仍保留，原因是：

- 命令面板和快捷键用户仍然可以直接调用
- `ManualMergeCommand` 仍复用 `DragSortModal`
- 兼容过渡阶段不会强行打断旧使用习惯

其中 `MergeToSidebarPreviewCommand` 的内部实现已经改为打开新的工作台视图，而不是旧的极简文本预览。

## 4. 统一的内容生成层

`src/services/ContentService.ts`

这是这次改造的核心。新的实现不再只返回“拼好的字符串”，而是同时支持“先拿到有序卡片列表，再决定如何展示或输出”。

### 4.1 关键接口

- `createSelectionSnapshot(selection)`
- `getOrderedCards(options)`
- `buildMergedContent(options)`
- `copyMergedContent(options, successNotice)`

### 4.2 选区快照

`createSelectionSnapshot` 会把当前选区转换为纯数据快照，包含：

- `id`
- `text`
- `x`
- `y`
- `width`
- `height`
- `badge`

这一步的意义是：

- 工作台内部不依赖 live selection
- 工作台被拖到独立窗口后仍能工作
- 排序切换、手动调整、预览渲染都基于同一份稳定输入

### 4.3 排序能力

`getOrderedCards` 统一支持三种模式：

- `position`
- `badge`
- `manual`

具体策略仍然复用领域层：

- `PositionSortStrategy`
- `BadgeSortStrategy`

`manual` 模式则根据 `manualOrderIds` 对快照重新排序。

### 4.4 输出内容构建

`buildMergedContent` 只负责根据排序结果返回：

- `content`
- `count`

当排序模式是 `badge` 且允许标记前缀时，输出格式为：

```text
[标记] 内容
```

其余模式输出纯文本段落。默认仍用空行分隔；如果用户开启 `insertDelimiterOnMerge`，则在相邻卡片之间插入当前 `canvasCardDelimiter`，格式为 `卡片 A`、空行、分隔符、空行、`卡片 B`。

## 5. 工作台状态服务

`src/services/PreviewWorkbenchService.ts`

这个服务负责维护工作台的一次性状态，而不是让 `ItemView` 自己承载全部业务逻辑。

### 5.1 状态结构

`src/types/WorkbenchState.ts`

当前工作台状态包含：

- `canvasFilePath`
- `canvasFileBasename`
- `selectionSnapshot`
- `sortMode`
- `manualOrderIds`
- `previewExpanded`
- `lastComputedContent`
- `isManualAdjusted`

### 5.2 主要职责

- 创建初始状态 `createState`
- 切换排序模式 `setSortMode`，切换时重建该模式下的自动顺序
- 维护手动拖拽顺序 `reorderManual`，并把 `isManualAdjusted` 标记为 `true`
- 保留预览展开状态 `setPreviewExpanded`
- 生成当前顺序对应的预览文本 `buildPreviewContent`

### 5.3 位置顺序微调

这次改造里最关键的一点是：

- 工作台打开时默认进入设置指定的排序模式，通常是 `位置`
- `位置` 以画布位置排序结果作为初始顺序
- `标记` 以数字标记排序结果作为初始顺序
- 用户可在当前模式下直接拖拽微调卡片顺序

因此“手动排序”不再作为独立菜单出现在主工作台里，而是收敛到当前排序模式后的微调能力。拖拽后输出路径会把当前顺序当作 `manual` 处理，但界面仍保留原始模式标签，用来决定是否给标记模式输出 `[标记]` 前缀。

## 6. 工作台视图实现

`src/presentation/views/MergeWorkbenchView.ts`

工作台基于 Obsidian 标准 `ItemView` 实现，类型仍沿用：

```ts
MERGE_PREVIEW_VIEW_TYPE = 'canvas-loom-merge-preview'
```

这让它天然支持：

- 在侧边栏打开
- 被拖成独立窗口
- 作为普通 tab 使用

打开工作台时会先查找现有 `canvas-loom-merge-preview` leaf：

- 找到时复用已有 leaf
- 发现多个旧实例时保留一个并 detach 其余 leaf
- 插件卸载时统一 detach 工作台 leaf，避免页面残留

### 6.1 三段式布局

当前视图分为三块：

1. 顶部工具栏
2. 中部顺序列表
3. 底部预览与输出区

### 6.2 顶部工具栏

顶部展示：

- 排序模式切换按钮：`位置 / 标记`
- 当前 Canvas 名称
- 选区快照数量
- 当前顺序和可输出卡片数

### 6.3 中部顺序列表

列表展示当前排序结果：

- `位置` 模式初始顺序按画布位置生成
- `标记` 模式初始顺序按数字标记生成

位置和标记模式下都支持拖拽。实现方式是视图内部监听原生拖拽事件：

- `dragstart`
- `dragover`
- `drop`
- `dragend`

拖拽完成后，通过 `PreviewWorkbenchService.reorderManual` 更新 `manualOrderIds` 和 `isManualAdjusted`。

### 6.4 底部预览区

预览页直接显示最终文本，标题区显示“卡片组预览”和当前快照信息。

当前已经落地的性能策略：

- 预览更新做了 `200ms` 防抖
- 输出按钮与预览区使用同一份当前顺序结果

### 6.5 输出按钮

工作台底部统一提供三个动作：

- `复制`
- `添加为新卡片`
- `新建文稿`

这三者都基于“当前工作台顺序”生成内容，只是输出目标不同。若当前模式是 `标记`，输出内容会保留 `[标记] 内容` 格式；若用户在标记模式下拖拽过，仍按当前拖拽顺序输出并保留标记前缀。

## 7. MergeService 的职责变化

`src/services/MergeService.ts`

在旧实现中，`MergeService` 更偏向“拿当前 selection 直接输出”。现在它扩展成了两个层次：

- 直接处理当前选区
- 处理来自工作台的选区快照
- 在合并为新卡片时按设置保留或删除源卡片

### 7.1 对外接口

当前主要接口包括：

- `mergeToCanvasCard`
- `mergeToSidebar`
- `mergeToMarkdown`
- `openWorkbench`
- `mergeSnapshotsToCanvasCard`
- `mergeSnapshotsToMarkdown`

### 7.2 打开工作台

`openWorkbench` 会做这些事：

1. 读取当前选区快照
2. 创建以位置顺序为初始值的工作台状态
3. 激活或复用右侧 `ItemView`
4. 把复制 / 添加为新卡片 / 新建文稿的回调注入到视图上下文

### 7.3 合并写入和源卡片清理

合并为新 Canvas 卡片时会先构造 `CanvasNodeData`：

- `text` 为合并后的正文
- `x` / `y` / `width` 来自排序后的第一张卡片
- `height` 为参与拼合卡片高度之和
- `id` 使用短随机字符串生成

写入时通过 `CanvasAdapter.mutateData` 在一次 Canvas 数据变更中完成：

- `keep-source`：追加合并卡片
- `delete-source`：先移除源节点和相关边，再追加合并卡片

最后只调用一次 `requestSave`。

### 7.4 自动恢复源 Canvas

工作台里的 `添加为新卡片` 不再依赖“原 Canvas 必须正处于激活状态”。

当前实现流程是：

1. 记录 `canvasFilePath`
2. 优先查找当前 workspace 已打开的对应 Canvas leaf
3. 如果没找到，则尝试自动打开对应 `.canvas`
4. 拿到新的 Canvas 实例后再执行 `addNode`

只有在这些情况下才会失败并提示：

- `.canvas` 文件不存在
- 文件路径失效
- 自动打开后仍未拿到 Canvas 实例

## 8. 设置项迁移

这次改造把旧设置：

- `mergeDefaultOrder`

迁移为：

- `defaultSortMode`

新增设置：

- `mergeCleanupMode`
  控制拼合为新卡片后保留或删除原卡片，默认 `keep-source`
- `insertDelimiterOnMerge`
  控制多卡片输出时是否在相邻卡片之间插入当前 `canvasCardDelimiter`，默认关闭

涉及文件：

- `src/settings/ICanvasLoomSettings.ts`
- `src/settings/CanvasLoomSettingTab.ts`
- `src/adapters/StorageAdapter.ts`

### 8.1 迁移策略

`StorageAdapter.loadSettings()` 中做了兼容迁移：

- 旧数据里如果存在 `mergeDefaultOrder`
- 且新字段 `defaultSortMode` 不存在
- 则自动把旧值映射到新字段

这样旧用户升级后不需要重新配置。

## 11. 回归建议

建议手测以下路径：

1. 多选后执行 `一键复制`
2. 多选后执行 `一键拼合`
3. 打开工作台后确认默认进入 `位置` 并按位置生成顺序
4. 在 `位置` 下拖拽调整顺序，确认输出跟随当前顺序
5. 在 `标记` 下拖拽调整顺序，确认输出保留标记前缀
6. 工作台执行 `复制 / 添加为新卡片 / 新建文稿`
7. 关闭原 Canvas 后，从工作台执行 `添加为新卡片`
8. 开启 `拼合后新建并删除原卡片` 后确认源卡片和相关边被移除
9. 反复打开工作台，确认不会出现多个侧边栏页面
10. 选中大量卡片时确认预览页标题与最终文本内容正确
11. 标记排序下确认无标记卡片排在最后且不被过滤
