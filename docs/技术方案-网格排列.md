# 技术方案：网格排列

## 背景

当前选区浮动工具栏里的能力已经收敛为“单轴整理”：水平时只调整 `x`，垂直时只调整 `y`，用于把已有卡片在一个方向上的间距整理均匀。

完整“排列”是另一个问题。它需要同时决定：

- 卡片顺序
- 每行或每列放多少张
- 什么时候断行或断列
- 水平和垂直间距
- 行内或列内对齐方式

因此网格排列应作为独立功能设计，不混入单轴整理。

## 目标体验

用户选中多张文本卡片后，可以把它们按网格重新摆放。

第一版建议提供：

- 排列方向：`先横后纵` / `先纵后横`
- 每行数量或每列数量
- 水平间距
- 垂直间距
- 对齐方式：先固定为左上对齐，后续再扩展

执行后会同时修改选中文本卡片的 `x` 和 `y`，并保存 Canvas。

## 与单轴整理的区别

单轴整理：

- 水平整理只改 `x`
- 垂直整理只改 `y`
- 不断行
- 不推断网格
- 保留另一轴上的手动布局关系

网格排列：

- 同时修改 `x` 和 `y`
- 明确支持断行或断列
- 会重建二维布局
- 适合把散乱卡片规整为矩阵

## 排序规则

网格排列仍需要先得到一个稳定的一维序列。

第一版建议复用现有位置排序设置：

- `Z 字排序`：从左到右，再从上到下
- `倒 N 排序`：从上到下，再从左到右

原因：

- 用户已经在设置中理解和使用这个顺序
- 复制、拼合和工作台已有同一套排序语义
- 网格排列是重建二维布局，使用明确顺序比推断空间路径更可解释

## 布局规则

### 先横后纵

适合普通阅读式网格。

```text
col = index % columns
row = floor(index / columns)

x = anchor.x + col * (cellWidth + horizontalGap)
y = anchor.y + row * (cellHeight + verticalGap)
```

### 先纵后横

适合列式任务流。

```text
row = index % rows
col = floor(index / rows)

x = anchor.x + col * (cellWidth + horizontalGap)
y = anchor.y + row * (cellHeight + verticalGap)
```

## 尺寸策略

第一版建议使用“各卡片原尺寸”推进位置：

- 同一行中，下一个卡片的 `x` 基于前一个卡片的 `x + width + horizontalGap`
- 换行时，下一行的 `y` 基于上一行最大高度加 `verticalGap`
- 同一列中，下一个卡片的 `y` 基于前一个卡片的 `y + height + verticalGap`
- 换列时，下一列的 `x` 基于上一列最大宽度加 `horizontalGap`

这样不强制统一尺寸，也不会修改卡片内容或大小。

## 锚点

排序后的第一张文本卡片作为锚点：

- 锚点的 `x` 和 `y` 不变
- 其他卡片相对锚点展开
- 只处理选中文本卡片
- 不修改边、颜色、标记、文本和尺寸

## UI 建议

网格排列不应和单轴整理放在同一个轻浮层里，否则控件会过重。

建议入口：

- 选区浮动工具栏新增一个独立按钮：`网格排列`
- 点击后打开轻量 Modal

Modal 字段：

- 排列方向：`先横后纵` / `先纵后横`
- 每行数量或每列数量
- 水平间距
- 垂直间距
- 执行按钮：`排列`

## 验收标准

- 选中 2 张以上文本卡片时可执行网格排列
- `先横后纵` 会按行断行
- `先纵后横` 会按列断列
- 水平和垂直间距分别生效
- 锚点位置保持不变
- 只修改选中文本卡片的 `x` / `y`
- 不修改卡片尺寸、内容、颜色、标记或边
- 执行后调用 Canvas 保存逻辑

## 暂不实现

以下能力不放入第一版：

- 自动根据视口宽度断行
- 根据选区包围盒自动推断行列数
- 居中、右对齐、底对齐
- 统一尺寸后再排列
- 按连接线方向推断顺序
