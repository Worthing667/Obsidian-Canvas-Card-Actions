# 技术实现细节

本文档只说明当前仍在使用的结构和主链路，避免和历史方案混在一起。

## 目录结构

- `src/main.ts`
  插件入口，负责初始化服务、注册命令和菜单。
- `src/adapters/`
  封装 Canvas、剪贴板、存储和文稿创建等外部交互。
- `src/domain/`
  放置卡片、标记模型和排序策略。
- `src/services/`
  负责拆分、标记、内容排序、拼合输出、工作台状态和选区浮动工具栏动作。
- `src/presentation/`
  放置命令、弹窗、视图和样式。
- `src/settings/`
  管理设置类型和设置页。

## 当前核心能力

- 单卡片复制
- 多卡片一键复制、一键拼合和 Loom工作台中的卡片组预览
- 单卡片拆分
- 标记、同色选择、属性管理和选区浮动工具栏一键排列
- Canvas 性能模式与性能诊断

## 多卡片主链路

多卡片相关功能已经统一为一条内容处理链路：

1. 从 Canvas 读取当前选区
2. 生成选区快照
3. 按排序模式得到有序卡片列表
4. 生成最终文本
5. 输出到剪贴板、Canvas 卡片、工作台或 Markdown 文稿

相关核心文件：

- `src/services/ContentService.ts`
- `src/services/MergeService.ts`
- `src/services/PreviewWorkbenchService.ts`
- `src/presentation/views/MergeWorkbenchView.ts`

## 为什么使用选区快照

- 让工作台和实时选区解耦
- 工作台被拖成独立窗口后仍可继续使用
- 打开工作台后，后续改动当前选区不会污染已有状态

快照至少包含：

- 节点 `id`
- 文本内容
- 坐标和尺寸
- 标记信息

## 排序实现

自动排序通过策略模式完成：

- `PositionSort`
- `BadgeSort`

工作台额外维护 `manualOrderIds`，用于在自动排序结果基础上继续手动微调。

## 工作台实现

工作台基于 Obsidian `ItemView`，由以下部分组成：

- 顶部工具栏：排序模式、Canvas 信息、卡片数量
- 中部顺序列表：位置模式下可拖拽
- 底部预览与输出区：默认折叠，展开后再生成文本

预览区的主要性能策略：

- 默认折叠
- 展开后才计算内容
- 预览更新带防抖

## 输出实现

- 剪贴板：通过 `ClipboardAdapter` 统一提示
- 新建 Canvas 卡片：以排序后的第一张卡片为锚点，继承它的位置和尺寸
- 新建 Markdown 文稿：由 `VaultAdapter` 在当前 `.canvas` 同目录生成文件

工作台创建新卡片时会优先尝试恢复源 Canvas，而不是要求原 Canvas 必须保持激活。

当 `mergeCleanupMode` 为 `delete-source` 时，新建合并卡片会和删除源卡片在同一次 Canvas 数据变更中完成，并同步移除指向源卡片的边。

## 设置项

当前主要设置项：

- `canvasCardDelimiter`
- `sortPriority`
- `enableBadges`
- `defaultSortMode`
- `mergeCleanupMode`
- `enablePerformanceMode`
- `enablePerformanceDiagnostics`
- `largeCanvasNodeThreshold`
- `badgeUpdateDebounceMs`

`StorageAdapter` 负责设置读取、保存和旧字段迁移。

## 标记能力

当前标记能力采用“单字段 + 数值友好排序”的实现：

- 只在 `.canvas` 节点上保存 `badge`
- 输入规则：`/^\d+(\.\d+)*$/`
- 排序规则：`localeCompare(undefined, { numeric: true })`
- 无标记卡片在标记排序时排在最后，组内仍按当前位置排序

`enableBadges` 现在是完整开关：

- 关闭时不再给节点补 `data-badge` 显示
- 跳过标记加载
- 清理 DOM 上的 `data-badge`
- 不需要运行时注入或移除样式

标记加载现在由 `BadgeRenderScheduler` 调度：

- `file-open` 后延迟加载当前 Canvas 标记
- 同一文件短时间内重复请求会被防抖合并
- 大 Canvas 会按批次在 `requestAnimationFrame` 中分帧写 DOM
- 插件卸载或关闭标记时会取消 pending timer 和 RAF

## Canvas 写入与性能

`CanvasAdapter` 提供 `mutateData(mutator)` 作为主要写入辅助：

- 读取当前 Canvas 数据
- 复制顶层对象、`nodes` 和 `edges`
- 在回调内集中修改
- 调用一次 `setData`

当前拆分卡片、拼合为新卡片并删除源卡片等流程已经使用该方法减少多次刷新。尺寸调整和排列仍保持一次读取、一次写入、一次保存。

`PerformanceService` 负责：

- 统计节点数、边数、文本卡片数、文件卡片数和带标记卡片数
- 根据 `largeCanvasNodeThreshold` 判断大 Canvas
- 在开启诊断时输出 `[Canvas Loom][perf]` 日志
- 包裹拆分、拼合、工作台打开、文稿创建等操作耗时

`enablePerformanceMode` 会在 `body` 上切换 `canvas-loom-performance-mode` class，具体视觉降载规则由根目录 `styles.css` 维护。

## 工作区生命周期

Loom工作台使用视图类型：

```ts
canvas-loom-merge-preview
```

打开工作台时会复用已有 leaf，并清理重复实例。插件卸载时会：

- 取消标记渲染调度
- 保留 Loom工作台 leaf，便于重新启用插件后继续复用
- 移除性能模式 class
- 移除标记样式
- 清理命令注册表

## 官方规范相关约束

当前代码结构额外遵守以下约束，这不是临时修补，而是后续开发默认边界：

- 插件样式统一放在根目录 `styles.css`
- 不运行时创建 `<style>` 节点
- 不直接使用 `innerHTML` / `outerHTML`
- UI 状态优先通过 class 切换表达
- Canvas 相关运行时对象通过显式类型收口，避免主链路 `any`
- Promise 在事件回调里要么显式处理，要么使用 `void` 表示有意忽略
- 获取当前 Canvas 上下文时避免依赖已废弃字段，优先使用当前 view 相关 API

这样做的原因不是一次性提审处理，而是这样才符合 Obsidian 官方规范，也更利于后续维护和版本兼容。
