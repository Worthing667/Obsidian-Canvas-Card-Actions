# 技术实现细节

本文档只说明当前仍在使用的结构和主链路，避免和历史方案混在一起。

## 目录结构

- `src/main.ts`
  插件入口，负责初始化服务、注册命令和菜单。
- `src/adapters/`
  封装 Canvas、剪贴板、存储和文稿创建等外部交互。
- `src/domain/`
  放置卡片、标记模型和排序策略。
- `src/services/`
  负责拆分、标记、内容排序、拼合输出、工作台状态、Canvas 卡片查找替换和选区浮动工具栏动作。
- `src/presentation/`
  放置命令、弹窗、视图和样式。
- `src/i18n/`
  放置语言识别、翻译函数、翻译类型和中英文字典。
- `src/settings/`
  管理设置类型和设置页。

## 当前核心能力

- 单卡片复制
- 多卡片一键复制、一键拼合和 Loom工作台中的卡片组预览
- Loom 工作台预览结果的 PNG 导出
- 单卡片拆分
- 标记、同色选择、属性管理、Canvas 卡片查找替换，以及选区浮动工具栏中的序号工具和单轴间距整理
- 英文和简体中文界面，根据 Obsidian 语言设置自动切换，也支持在插件设置中手动指定语言
- Canvas 性能模式与性能诊断

## 多卡片主链路

多卡片相关功能已经统一为一条内容处理链路：

1. 从 Canvas 读取当前选区
2. 生成选区快照
3. 按排序模式得到有序卡片列表
4. 生成最终文本
5. 输出到剪贴板、Canvas 卡片、工作台或 Markdown 文稿

相关核心文件：

- `src/services/ContentService.ts`
- `src/services/MergeService.ts`
- `src/services/PreviewWorkbenchService.ts`
- `src/presentation/views/MergeWorkbenchView.ts`

## 为什么使用选区快照

- 让工作台和实时选区解耦
- 工作台被拖成独立窗口后仍可继续使用
- 打开工作台后，后续改动当前选区不会污染已有状态

快照至少包含：

- 节点 `id`
- 文本内容
- 坐标和尺寸
- 标记信息

## 排序实现

自动排序通过策略模式完成：

- `PositionSort`
- `SequenceSort`

工作台额外维护 `manualOrderIds`，用于在自动排序结果基础上继续手动微调。

## 工作台实现

工作台基于 Obsidian `ItemView`，现在是一个三模式侧栏容器：

- 顶部工具栏：Canvas 信息、当前模式下的卡片数量和清空动作
- 一级功能切换：`预览` / `排序` / `查找`
- `排序` 面板：位置排序、序号排序和手动拖拽
- `预览` 面板：按当前工作台顺序生成文本，并输出到剪贴板、新 Canvas 卡片或 Markdown 文稿
- `查找` 面板：当前画布/当前选区的文本卡片查找替换，结果点击后选中并定位对应 Canvas 卡片，不额外添加 Canvas 高亮

预览区的主要性能策略：

- 预览页直接显示最终文本
- 预览更新带防抖

## 输出实现

- 剪贴板：通过 `ClipboardAdapter` 统一提示
- 新建 Canvas 卡片：以排序后的第一张卡片为锚点，继承它的位置和宽度；先以参与拼合卡片高度之和创建，再在运行时节点可用时自动贴合合并文本高度。运行时 API 不可用时保留初始高度，不影响创建结果
- 新建 Markdown 文稿：由 `VaultAdapter` 在当前 `.canvas` 同目录生成文件
- PNG 图片：`MergeWorkbenchView` 刷新当前预览后触发 `WorkbenchImageExportService`；单卡片右键菜单由 `ExportSingleCardAsImageCommand` 触发同一渲染服务；`HtmlToImageWorkbenchRenderer` 将预览或卡片 DOM 渲染为 PNG，`VaultAdapter.createWorkbenchPreviewImage` 按用户选择的仓库文件夹写入二进制文件

图片导出是预览面板的一个输出动作，与复制、新建 Canvas 卡片和新建 Markdown 文稿共用当前工作台状态：

1. 点击导出时同步生成当前预览文本
2. 用当前工作台排序、分隔符和文本更新预览 DOM
3. 根据预览区的完整滚动尺寸展开渲染副本，移除副本滚动条后以 2 倍像素比例输出，不读取 Canvas 卡片位置或连线
4. 过滤嵌入媒体和非元素节点；字体嵌入关闭，避免主动获取外部资源
5. 通过文件夹选择器取得目标目录，使用当前 `.canvas` 文件和工作台快照的卡片数量写入 PNG

图片渲染通过 `ownerDocument.defaultView` 获取计算样式，保证工作台位于弹出窗口时仍使用正确的 DOM 上下文。过滤器会放行文本节点，避免渲染库遍历预览内容时因 `classList` 不存在而失败。

工作台创建新卡片时会优先尝试恢复源 Canvas，而不是要求原 Canvas 必须保持激活。

当 `mergeCleanupMode` 为 `delete-source` 时，新建合并卡片会和删除源卡片在同一次 Canvas 数据变更中完成，并同步移除指向源卡片的边。

## 国际化实现

插件内置英文和简体中文两套界面文案。默认 `language` 为 `auto`，运行时会读取 Obsidian 语言配置并解析当前界面语言：中文环境使用 `zh-CN`，其它语言环境回退到 `en`。

相关核心文件：

- `src/i18n/language.ts`
  负责规范化语言设置、读取 Obsidian 语言候选值并解析实际语言。
- `src/i18n/index.ts`
  提供 `t()` 翻译函数，按当前设置选择字典并处理 `{param}` 形式的参数替换。
- `src/i18n/dictionaries/en/`
  英文字典。
- `src/i18n/dictionaries/zh-CN/`
  简体中文字典。
- `src/settings/CanvasLoomSettingTab.ts`
  在设置页提供 `自动`、`English`、`简体中文` 三种语言选项。

所有用户可见的命令名、设置项、通知、弹窗、工作台和查找替换面板文案都应通过 `t()` 获取，避免新增硬编码界面文本。

## 标记能力

当前标记能力采用独立 `badge` 字段保存：

- 只在 `.canvas` 节点上保存 `badge`
- 输入规则：`/^\d+(\.\d+)*$/`
- 序号排序优先解析正文第一行，缺失时回退到 `badge`
- 无序号卡片排在最后，组内仍按当前位置排序

多选文本卡片时，`CanvasSelectionToolbarService` 在选区浮动工具栏中注入序号工具按钮：

- 批量编号弹窗按画布位置生成连续序号
- 混合选区默认只处理无标记节点，并允许切换为重新编号全部节点
- 标记移除直接在浮动面板执行，只统计和写入实际带标记的节点
- 右键菜单和命令面板入口复用同一个浮动面板；右键菜单作为可逐步移除的过渡入口
- `BadgeService` 会过滤无变化写入，避免无意义的 `setData()` 和 `save()`

`enableBadges` 现在是完整开关：

- 关闭时不再给节点补 `data-badge` 显示
- 跳过标记加载
- 清理 DOM 上的 `data-badge`
- 不需要运行时注入或移除样式

标记加载现在由 `BadgeRenderScheduler` 调度：

- `file-open` 后延迟加载当前 Canvas 标记
- 同一文件短时间内重复请求会被防抖合并
- 大 Canvas 会按批次在 `requestAnimationFrame` 中分帧写 DOM
- 插件卸载或关闭标记时会取消 pending timer 和 RAF

## Canvas 写入与性能

`CanvasAdapter` 提供 `mutateData(mutator)` 作为主要写入辅助：

- 读取当前 Canvas 数据
- 复制顶层对象、`nodes` 和 `edges`
- 在回调内集中修改
- 调用一次 `setData`

当前拆分卡片、拼合为新卡片并删除源卡片等流程已经使用该方法减少多次刷新。尺寸调整和排列仍保持一次读取、一次写入、一次保存。

`PerformanceService` 负责：

- 统计节点数、边数、文本卡片数、文件卡片数和带标记卡片数
- 根据 `largeCanvasNodeThreshold` 判断大 Canvas
- 在开启诊断时输出 `[Canvas Loom][perf]` 日志
- 包裹拆分、拼合、工作台打开、文稿创建等操作耗时

`enablePerformanceMode` 会在 `body` 上切换 `canvas-loom-performance-mode` class，具体视觉降载规则由根目录 `styles.css` 维护。当前规则包括：

- 对 Canvas 节点启用 `contain: layout paint`
- 对 Canvas 节点内容设置 `backface-visibility: visible`
- 性能模式下关闭 badge 的动画和阴影
- 低缩放时将 badge 从数字胶囊降级为小圆点

`CanvasPerformanceModeService` 负责把渲染降级状态同步到 Canvas wrapper：

- 普通 Canvas 在实际倍率 `scale <= 0.6` 时设置 `data-canvas-loom-badge-mode="compact"`
- 大 Canvas 在实际倍率 `scale <= 0.8` 时更早进入 compact；大 Canvas 判定复用 `largeCanvasNodeThreshold`
- 优先读取运行时 `canvas.scale`；缺失时将内部 `zoom` / `tZoom` 按 `2 ** value` 转换为实际倍率
- 同步频率为低频轮询，并用 `WeakMap` 避免对同一 wrapper 重复写入相同状态
- 节点数量优先读取 `canvas.nodes.size`，缺失时才兜底读取 Canvas 数据

## 工作区生命周期

Loom工作台使用视图类型：

```ts
canvas-loom-merge-preview
```

打开工作台时会复用已有 leaf，并清理重复实例。插件卸载时会：

- 取消标记渲染调度
- 保留 Loom工作台 leaf，便于重新启用插件后继续复用
- 移除性能模式 class
- 移除标记样式
- 清理命令注册表

## 官方规范相关约束

当前代码结构额外遵守以下约束，这不是临时修补，而是后续开发默认边界：

- 插件样式统一放在根目录 `styles.css`
- 不运行时创建 `<style>` 节点
- 不直接使用 `innerHTML` / `outerHTML`
- UI 状态优先通过 class 切换表达
- Canvas 相关运行时对象通过显式类型收口，避免主链路 `any`
- Promise 在事件回调里要么显式处理，要么使用 `void` 表示有意忽略
- 获取当前 Canvas 上下文时避免依赖已废弃字段，优先使用当前 view 相关 API

这样做的原因不是一次性提审处理，而是这样才符合 Obsidian 官方规范，也更利于后续维护和版本兼容。
